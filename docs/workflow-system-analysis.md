# MoviePilot Go 工作流系统目录分析文档

## 1. 整体架构概述

MoviePilot Go 工作流系统采用了分层架构设计，主要分为四个核心目录，实现了从工作流定义到执行的完整生命周期管理。系统支持多种执行模式（同步、异步、并行），提供了18种内置动作，覆盖了文件处理、资源获取、过滤、核心业务等多个方面。

```
┌──────────────────────────────────────────────────────────────────────┐
│                        Workflow System                              │
├────────────────┬─────────────────────────────────────────────────────┤
│                │                                                     │
│  Workflow      │                    Actions System                   │
│  Engine        │  ┌─────────────┬────────────────┬────────────────┐ │
│                │  │             │                │                │ │
│                │  │  Actions    │   Adapters     │     Params     │ │
│                │  │             │                │                │ │
│                │  └─────────────┼────────────────┼────────────────┘ │
│                │                │                │                  │
│                │                │ 调用核心业务服务 │ 提供参数定义和验证  │
└────────────────┴────────────────┴────────────────┴──────────────────┘
```

## 2. 详细目录分析

### 2.1 顶层工作流目录：`/internal/business/workflows/`

**核心作用**：工作流系统的核心实现，包含工作流引擎和工作流定义

**目录结构**：
```
workflows/
├── workflow.go      # 工作流接口和基础引擎
├── engine.go        # 完整的工作流执行引擎
└── actions/         # 动作系统（子目录）
```

**核心组件**：

| 文件 | 功能描述 | 关键接口/结构体 |
|------|----------|----------------|
| `workflow.go` | 定义工作流和步骤的基础接口 | `Workflow` 接口：定义工作流执行<br>`Step` 接口：定义步骤执行<br>`Engine` 结构体：基础引擎实现 |
| `engine.go` | 完整的工作流执行引擎 | 支持同步、异步、并行执行<br>支持暂停、恢复、取消、回滚<br>完整的状态管理 |

**设计特点**：
- 接口驱动设计，便于扩展新的工作流类型
- 支持多种执行模式，适应不同场景需求
- 完整的状态管理，支持工作流执行的全生命周期
- 与动作系统紧密集成，支持多种动作类型

### 2.2 动作系统目录：`/internal/business/workflows/actions/`

**核心作用**：实现工作流中可执行的具体动作，是工作流系统的核心功能单元

**目录结构**：
```
actions/
├── factory.go              # 动作工厂，负责注册和创建动作
├── base_structs.go         # 基础数据结构和接口
├── services.go             # 服务接口定义
├── params.go               # 参数解析和验证
├── manager.go              # 动作管理器
├── chain.go                # 动作链实现
├── *_action.go             # 18种内置动作的实现
├── adapters/               # 服务适配器（子目录）
└── params/                 # 动作参数定义（子目录）
```

**核心组件**：

| 组件 | 功能描述 | 设计模式 |
|------|----------|----------|
| **Action Factory** | 注册和创建所有动作实例 | 工厂模式 |
| **Base Action** | 所有动作的基础实现，提供通用功能 | 模板方法模式 |
| **Action Context** | 动作执行上下文，共享数据载体 | 上下文模式 |
| **Service Interfaces** | 动作所需的服务接口定义 | 依赖倒置原则 |
| **Action Manager** | 管理动作的生命周期 | 管理器模式 |
| **Action Chain** | 支持顺序执行多个动作 | 责任链模式 |

**内置动作分类**：

| 类别 | 动作名称 | 功能描述 |
|------|----------|----------|
| **文件处理** | scan_file | 扫描文件系统，获取文件列表 |
| | scrape_file | 刮削文件元数据 |
| | transfer_file | 转移文件到目标位置 |
| | delete_file | 删除文件 |
| | copy_file | 复制文件 |
| | move_file | 移动文件 |
| **资源获取** | fetch_torrents | 获取种子资源 |
| | fetch_rss | 获取RSS订阅 |
| | fetch_medias | 获取媒体信息 |
| | fetch_downloads | 获取下载任务 |
| **过滤** | filter_torrents | 过滤种子资源 |
| | filter_medias | 过滤媒体信息 |
| **核心业务** | add_download | 添加下载任务 |
| | add_subscribe | 添加媒体订阅 |
| | send_message | 发送通知消息 |
| **系统功能** | invoke_plugin | 调用系统插件 |
| | send_event | 发布系统事件 |
| | note | 记录笔记 |

**设计特点**：
- 工厂模式实现动作的动态注册和创建
- 依赖注入机制，通过ServiceContainer注入所需服务
- 统一的BaseAction接口，简化动作开发
- 内置缓存机制，避免重复执行
- 支持事件发布，便于系统集成

### 2.3 服务适配器目录：`/internal/business/workflows/actions/adapters/`

**核心作用**：桥接动作系统与核心业务服务，实现松耦合设计

**目录结构**：
```
adapters/
├── download_adapter.go      # 下载服务适配器
├── event_adapter.go         # 事件服务适配器
├── plugin_adapter.go        # 插件服务适配器
├── rss_adapter.go           # RSS服务适配器
├── media_adapter.go         # 媒体服务适配器
├── notification_adapter.go  # 通知服务适配器
└── subscribe_adapter.go     # 订阅服务适配器
```

**核心组件**：

| 适配器 | 服务类型 | 主要功能 | 实现特点 |
|--------|----------|----------|----------|
| `download_adapter` | 下载服务 | 管理下载任务 | 支持模拟实现，便于测试 |
| `event_adapter` | 事件服务 | 发布系统事件 | 支持多种事件类型 |
| `plugin_adapter` | 插件服务 | 调用系统插件 | 支持动态加载插件 |
| `rss_adapter` | RSS服务 | 处理RSS订阅 | 支持多种RSS格式 |
| `media_adapter` | 媒体服务 | 管理媒体信息 | 支持媒体识别和匹配 |
| `notification_adapter` | 通知服务 | 发送系统通知 | 支持多种通知渠道 |
| `subscribe_adapter` | 订阅服务 | 管理媒体订阅 | 支持订阅的增删改查 |

**设计特点**：
- 适配器模式，解耦动作系统与核心业务服务
- 统一的服务接口，简化动作开发
- 支持模拟实现，便于测试和开发
- 面向接口编程，便于替换和扩展实现

### 2.4 动作参数目录：`/internal/business/workflows/actions/params/`

**核心作用**：定义所有动作的参数结构，支持参数验证和配置

**目录结构**：
```
params/
├── base_params.go           # 基础参数结构
├── add_download_params.go   # 添加下载参数
├── add_subscribe_params.go  # 添加订阅参数
├── fetch_torrents_params.go # 获取种子参数
├── fetch_downloads_params.go # 获取下载参数
├── scrape_file_params.go    # 刮削文件参数
├── scan_file_params.go      # 扫描文件参数
├── invoke_plugin_params.go  # 调用插件参数
├── send_event_params.go     # 发送事件参数
├── fetch_rss_params.go      # 获取RSS参数
├── fetch_medias_params.go   # 获取媒体参数
├── filter_medias_params.go  # 过滤媒体参数
├── send_message_params.go   # 发送消息参数
├── filter_torrents_params.go # 过滤种子参数
├── transfer_file_params.go  # 转移文件参数
└── note_params.go           # 记录笔记参数
```

**核心组件**：

| 文件 | 功能描述 | 关键特性 |
|------|----------|----------|
| `base_params.go` | 基础参数结构和接口 | 支持循环执行配置<br>参数验证机制 |
| `*_params.go` | 各动作的具体参数定义 | 包含动作特定的配置项<br>实现参数验证 |

**参数结构设计**：
- 所有参数结构体都嵌入 `BaseParamsStruct`
- 实现 `BaseParams` 接口，支持循环执行和参数验证
- 使用 `mapstructure` 标签，支持从映射解码
- 每个动作对应一个参数文件，便于维护和扩展

**参数验证**：
- 基础参数验证：检查循环执行配置的合法性
- 动作特定验证：检查动作所需参数的合法性
- 提供友好的错误信息

## 3. 工作流执行流程

### 3.1 工作流定义与执行

1. **工作流定义**：创建包含多个步骤的工作流，每个步骤指定一个动作和参数
2. **引擎调用**：工作流引擎根据工作流定义调用具体的动作执行
3. **动作工厂**：根据动作名称从工厂中获取动作实例
4. **参数解析**：从配置中解析动作参数，并进行验证
5. **服务适配**：通过适配器调用核心业务服务
6. **执行结果**：动作执行完成后，返回结果并更新工作流状态
7. **事件发布**：必要时发布系统事件，通知其他组件

### 3.2 动作执行流程

1. **动作创建**：通过工厂模式创建动作实例
2. **服务注入**：注入所需的服务依赖
3. **参数解析**：解析并验证动作参数
4. **上下文准备**：准备动作执行上下文
5. **执行动作**：调用动作的Execute方法
6. **结果处理**：处理执行结果，更新上下文
7. **缓存更新**：保存执行结果到缓存
8. **事件发布**：发布相关事件

## 4. 设计优势

### 4.1 分层设计
- **清晰的职责划分**：各目录职责明确，便于维护和扩展
- **松耦合设计**：通过接口和适配器实现组件间的解耦
- **单向依赖**：严格遵循分层依赖规则，避免循环依赖

### 4.2 接口驱动设计
- **基于接口编程**：所有组件通过接口交互，便于替换和扩展实现
- **依赖倒置**：高层模块不依赖低层模块的具体实现，只依赖接口
- **便于测试**：可以轻松替换为模拟实现，进行单元测试

### 4.3 插件化架构
- **动态注册**：支持动态注册新动作，无需修改核心代码
- **可扩展设计**：便于添加新的动作类型和服务适配器
- **灵活配置**：支持通过配置文件定义工作流，无需修改代码

### 4.4 事件驱动
- **组件间通信**：通过事件系统实现组件间的松耦合通信
- **异步处理**：支持异步事件处理，提高系统性能
- **可扩展性**：便于添加新的事件类型和处理逻辑

### 4.5 完整的状态管理
- **执行状态**：支持多种执行状态（pending、running、completed、failed、cancelled）
- **生命周期管理**：支持工作流执行的全生命周期管理
- **状态恢复**：支持从失败状态恢复执行

## 5. 与其他系统的集成

### 5.1 核心业务服务
工作流系统通过适配器与核心业务服务集成，包括：
- 下载服务：管理下载任务
- 媒体服务：管理媒体信息
- 订阅服务：管理媒体订阅
- 通知服务：发送系统通知
- 插件服务：调用系统插件

### 5.2 事件系统
工作流系统与事件系统紧密集成，支持：
- 事件触发工作流执行
- 工作流执行过程中发布事件
- 事件驱动的工作流步骤

### 5.3 API层
工作流系统通过API层暴露HTTP接口，支持：
- 工作流的创建、更新、删除和查询
- 工作流的执行和停止
- 工作流执行状态的查询

## 6. 总结

MoviePilot Go 工作流系统采用了现代化的分层架构设计，具有良好的扩展性和可维护性。系统提供了完整的工作流引擎，支持多种执行模式和步骤类型；动作系统提供了18种内置动作，覆盖了文件处理、资源获取、过滤、核心业务等多个方面；服务适配器实现了与核心业务服务的解耦；动作参数系统支持灵活的参数配置和验证。

系统的设计优势包括：分层设计、接口驱动、插件化架构、事件驱动和完整的状态管理。这些设计特点使得工作流系统能够适应复杂的业务场景，支持灵活的扩展和定制，为MoviePilot提供了强大的自动化处理能力。

通过工作流系统，MoviePilot可以实现复杂的自动化工作流，如：
- 自动扫描下载目录，刮削文件元数据，转移到媒体库
- 定时获取RSS订阅，过滤种子，添加下载任务
- 监控下载完成事件，自动整理文件，发送通知

工作流系统是MoviePilot的核心组件之一，为系统提供了强大的自动化处理能力，提高了系统的灵活性和可扩展性。
